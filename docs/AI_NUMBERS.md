# 2026-10-13 — 업그레이드 카드

기획자가 단계·카드 구성을 직접 지시했다. **AI가 정한 것은 `value` 열뿐**이다
(승인된 방식: "1차는 네가 넣고 이후 CSV로 고친다").

| 지시받은 것 | 지시 내용 |
|---|---|
| 한 번에 몇 장 | **3장** |
| 2단계 | 이동 속도 · 로프 길이 2배 · 장애물로 잔해 안 떨어짐 |
| 3단계 | 고르지 않은 두 가지 + 약한 자성 |
| 5단계 | 구멍이 따라다님 · 타수 2배 |
| 6단계 | 건물 삼킴 **하나만** |
| 감속 곡선 | **하지 않는다** |
| 경험치 | **1.5배** |
| 흡인 범위 | "너무 멀지 않게" |
| 추천 셋 | 셋 다 넣음 (경험치 · 흡인 범위 · 스치면 잡힘) |

**AI가 정한 값**: 이동 속도 1.25 · 로프 2.0 · 흩어짐 0.7 · 스침 여유 1.0(반지름 배) ·

## 지시와 다르게 된 것 — 밝혀 둔다

- **타수 2배**를 5단계가 아니라 **4단계**로 내렸다. 5단계에 네 장이 몰려
  "3장"이 깨졌기 때문이다. 기획자에게 알리고 넘어갔다.
- **약한 자성**(3단계)과 **건물 삼킴**(6단계)을 아직 안 만들었다. 표에서 뺐다 —
  고르면 아무 일도 안 하는 카드가 되기 때문이다. 그래서 지금은 **10장이고 다섯 번 고른다**.
  건물 삼킴이 들어가면 6단계가 지급으로 바뀌어 **네 번 고르기**가 된다.

## 실측으로 확인한 것

- 단계마다 3장이 뜨고, 안 고른 카드가 다음 단계에 다시 올라온다 (두 판을 돌려 확인)
- 판이 바뀌면 배율이 1로 돌아간다
- 스침 판정: 10x10 고리 기준, 바깥 0.30m의 작은 조각(반지름 0.37)은 잡히고
  바깥 1.50m의 큰 조각(반지름 1.29)은 안 잡힌다

# 사운드 네 가지 고침 [지시 2026-10-14]

기획자 지적: ① 발소리가 섞여 난다 ② 타격음이 둔탁하다 ③ 붕괴가 늘어진다
④ 붕괴가 타격을 묻는다.

## 지적과 실측이 다른 곳 — 밝혀 둔다

**② "클립 할당이 잘못됐다"는 아니었다.** `Strike`는 `SFX_Strike_01~03`을 바로
가리키고 있었고 유니티 임포트도 최신이었다. **파일 안의 소리가 둔탁했다** —
300Hz 아래 93.5%, 500Hz 위 2.3%.

**내가 10/14에 "저역 78~82% · 고역 11~15%"라고 보고한 숫자는 틀렸다.**
섞는 중간 단계를 재고 **쓰여진 파일을 재지 않았다.** 그래서 `make_strike.py`가
이제 저장한 파일을 다시 읽어 잰다(`read_back`).

**④ 볼륨 값이 원인이 아니었다.** RMS는 타격 -17.8 / 붕괴 -17.6으로 이미 거의 같았다.
붕괴가 타격을 묻은 것은 **길이(7.24초 vs 0.30초)** 와 **대역**(붕괴는 고역 62.8%,
타격은 2.3% — 귀가 제일 민감한 대역에 붕괴만 있었다) 때문이다.

## 찾아낸 버그 둘

**하이패스가 거꾸로 동작했다.** `highpass(x) = x - lowpass(x)`는 저역통과가 입력과
위상이 맞을 때만 상쇄된다. 차수를 올리면 위상이 밀려 저역이 남는다 — 600Hz에서
실측 order=1은 27.9%, **order=8은 79.1%**. 가파르게 하려면 같은 필터를 여러 번 건다.
`order=2`를 "가파르다"로 읽어 폰 스피커용 중역 겹이 제 몫을 못 하고 있었다.

**발소리 변형 셋이 서로 다른 소리였다.** 01은 고역 96.6%(쉭), 02는 저역 97.4%(쿵),
03은 피크가 8~11dB 크다. 10/08 VARCO가 뽑은 것을 변형으로 물려 둔 것이고,
`make_sfx.py`의 발소리 레시피는 `# 비상용`이라 한 번도 안 돌았다.

한 발의 타격음을 1로 봤을 때 귀에 닿는 양 (RMS x 길이 x 음량):

| | 전 | 후 |
|---|---|---|
| 건물 파괴 | **24배** | **8.6배** |
| 층 붕괴 | - | 2.7배 |
| 발걸음 | - | 0.1배 |

- 발소리 겹침: 클립 0.11초 < `minGap` 0.12초 ⇒ **구조적으로 겹칠 수 없다**
  (걸음 간격은 2.2m / 6m/s = 0.37초)
- 붕괴 변형끼리 차이: 1.3~1.9dB (원본 0dB. 한 장씩 피크로 맞추면 **7dB로 벌어진다**)

## 남은 위험 — 기획자 판단이 필요하다

`SFX_Footstep_02.wav` · `SFX_Footstep_03.wav`가 폴더에 남아 있다.

그 메뉴를 한 번 누르면 셋이 다시 물려 발소리 버그가 돌아온다.

# 타격음 다시 — 받은 음원 여섯을 실제로 쓴다 [지적 2026-10-14]

# 타격음·발소리 전면 재작업 — 받은 음원만 쓴다 [지시 2026-10-14]

기획자 지시: **"내가 준 7개의 파일만 넣으라 했는데 왜 또 임의로 판단하는거지? 제대로 해.
원래의 음원 폐기후 다시 작업할것. 걸을 때 사운드는 robot_stamp (3)쪽 사운드를 써."**

## 내가 임의로 한 것 — 걷어낸 목록

| 무엇 | 왜 틀렸나 |
|---|---|
| 대역 필터로 음원을 깎음 | 받아 온 소리에서 뭘 버릴지는 내가 고를 일이 아니다 |
| 겹마다 배합비(SHARE_*)를 정함 | 누가 크고 작을지도 마찬가지다 |
| 발소리를 소음으로 **합성** | `robot_stamp`를 두고 내가 지어냈다 |

`Tools/make_strike.py`를 **지우고 다시 썼다.** 남은 손질은 게임의 박자가 강제하는 것뿐이다:

1. 앞 무음 떼기 (일곱 중 여섯이 24~1205ms 뒤에야 소리가 난다)
2. 0.30초로 자르기 (초당 다섯 번이라 간격이 0.2초)
3. 끝 내리기 (안 하면 잘린 자리에서 '툭')
4. 변형끼리 음량 맞추기 — **대역은 안 건드린다**

셋은 **같은 에너지**로 겹친다. 비율을 정하지 않는다.

## 받은 일곱 장

`firecracker_bang (1)(2)(3)` · `cannon_fire (1)(2)(3)` · `fighting_sound (1)`
— 전부 쓴다. 변형 하나가 세 장을 쓰고, `fighting_sound`는 한 장뿐이라 셋이 같이 쓴다.

## 발소리 — `robot_stamp (3)`

**이 파일에는 걸음이 15번 들어 있다** (0.16 · 0.37 · 0.58 · 0.78 … 초, 약 0.20초 간격).
그대로 꽂으면 한 걸음에 열다섯 걸음이 쏟아진다. 그래서 `Tools/cut_footstep.py`가
**제일 센 걸음 하나**를 떼어낸다 — 1.96초~2.17초, **0.211초**.

**길이를 내가 정하지 않는다.** 다음 걸음이 시작하는 자리가 끝이다.

`make_sfx.py`의 합성 발소리 레시피는 RECIPES에서 빼고 `NotImplementedError`로 막았다 —
남겨 두면 기획자가 지정한 음원을 합성음으로 덮어쓴다.

## 결과 (실측)

| | 값 |
|---|---|
| 타격 저역 / 고역 | 64.6~80.6% / 15.7~32.6% |
| 타격 변형끼리 RMS | **-19.2 셋 다 같음** (맞추기 전 -13.9 / -19.2 / -16.4, **5.3dB 차이**) |
| 발소리 | 0.211초 · 저역 94.6% (robot_stamp가 그런 소리다) |
| 발소리 `minGap` | 0.12 -> **0.22** (클립 0.211초보다 길어야 안 겹친다) |

**대역 비율은 재서 적을 뿐 거기에 맞추지 않았다.** 받은 음원이 가진 그대로다.

## 음량 맞추기만 남긴 이유

필터와 배합비를 걷어내니 변형 셋이 **5.3dB 벌어졌다.** 칠 때마다 크기가 들쭉날쭉한데,
그게 발소리에서 지적받은 "소리가 일정하지 않음"과 같은 증상이다.
음량은 **음원에서 뭘 버리는 일이 아니라서** 남겼다 — 어느 대역을 깎을지 고르는 것과 다르다.
`MATCH_LEVEL = False`로 끄면 원본 그대로 나온다.

제일 조용한 변형에 맞춘다. 평균에 맞추면 조용한 쪽을 올려야 하는데 피크 천장에 걸려
5.3dB가 3.0dB까지밖에 안 줄었다. 내리는 것은 언제나 되므로 최소에 맞추면 정확히 맞는다.

# 발소리는 뼈를 본다 · 타격음 7종 랜덤 [지시 2026-10-14]

## 발소리 — 위상표를 버리고 발가락 뼈 높이로

처음에는 클립마다 발이 닿는 위상을 재서 표로 들고 블렌드에 따라 보간했다.
끝점은 맞았지만 **중간에서 깨졌다** — blend 0.6에서 오른발이 0.29가 아니라
**0.66~0.77**에 바닥에 있었다. 두 클립을 섞으면 자세가 섞이는 것이지
착지 시점이 섞이는 것이 아니다.

**발이 언제 닿는지는 발가락 뼈가 이미 알고 있다.** 높이가 바닥 근처로 내려오는
순간이 착지다. 블렌드·클립·배속과 무관하게 언제나 맞는다.

### 고친 값 셋 — 전부 실측으로 골랐다

| 값 | 선택 | 왜 |
|---|---|---|
| `plantMargin` | **0.01m** | 바닥에서 1cm 안. **비율이 아니라 거리**인 이유: 발이 뜨는 높이가 걷기 13cm / 달리기 69cm로 다섯 배 다르다. 비율(12%)로 잡으니 달리기 문턱이 땅에서 17.8cm라 **131ms 먼저** 울렸다 |
| `rearmAt` | **0.55** | 범위의 55%까지 떠야 다음 착지를 받는다 |
| `forget` | **6초** | 높낮이를 재는 구간. 걷기 한 바퀴(1.125초)보다 길어야 한다 |

**지수 감쇠를 구간 최소/최대로 바꿨다.** 매 프레임 조금씩 좁히면 평형에서 창이
늘 실제보다 좁고, 그러면 문턱이 뜻을 잃는다 — 1.2초짜리 감쇠는 **한 바퀴에 범위의
94%를 좁혔다**. 구간을 통째로 갈아 끼우면 줄어들지 않는다.

### 검증 (실측)

| | 횟수/바퀴 | 발 바닥 위상 | 울린 위상 | 어긋남 |
|---|---|---|---|---|
| Walk 1.125초 | **2.0** | 0.30 / 0.80 | 0.27 / 0.78 | **37ms / 28ms** |
| Run 0.625초 | **2.0** | 0.38 / 0.90 | 0.33 / 0.88 | **31ms / 16ms** |

걷기에서 발가락은 한 바퀴에 **두 번** 내려온다 — 진짜 착지(바닥 0cm)와
발끝을 굴리는 얕은 골(2.8cm 위)이다. 1cm 문턱이 그 사이를 가른다.
여유를 0.03m로 하면 걷기가 3회가 되고, 0.006m면 2회지만 가장자리다.

## 타격음 — 7종 랜덤, 피치 조절 없음

`SOURCES`를 **받은 일곱 장 전부**로. 사운드뱅크 `Strike`에 7장을 물리고
**`pitchJitter` 0.12 -> 0**으로 껐다 [지시 "피치 조절등을 하지 않고"].

**직전에 쓴 것은 다시 안 고른다** [더함]. 그냥 무작위면 7장이어도 일곱 번에 한 번은
같은 것이 두 번 연속 나오고, 초당 다섯 번 치는 소리라 그 한 번이
"사운드 변함이 안 느껴진다"로 들린다. 7만 번 뽑기에 **연속 중복 0번**, 분포 균등.

## 사고 둘 — 둘 다 "확인했다"가 거짓이었다

**① 컴파일 실패를 못 봤다.** 파이썬이 Tooltip 문자열 안에 `\n`을 **진짜 줄바꿈으로
펼쳐** 넣어 C# 문법이 깨졌다. 유니티는 **조용히 마지막으로 성공한 어셈블리를 계속 쓴다.**
`isCompiling`을 컴파일이 *시작되기 전에* 읽어 통과시켰고 콘솔 에러도 0으로 보였다.
